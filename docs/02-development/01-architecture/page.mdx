# Architecture

Dependency Links has one VS Code extension-host runtime and multiple browser webview runtimes.

## Runtime layout

```text
Extension host
├── document links
├── Inspector webview
└── Dependency Graph webview

Browser-safe shared code
├── src/shared/
└── src/utils/
```

Each webview has its own browser entry point while sharing UI, VS Code state wrappers, styles, dependency types, and dependency parsing/resolution utilities.

## Extension host

`src/extension.ts` is the VS Code entry point.

It is responsible for:

- registering document link providers
- registering `dependencyLinks.openPanel`
- registering `dependencyLinks.openDependencyGraph`
- creating webview panels
- resolving editor document links through VS Code APIs
- owning webview lifecycle and CSP

Dependency input entered inside a webview does not round-trip through the extension host.

## Dependency parsing and resolution

Browser-safe dependency utilities live under:

```text
src/utils/
├── parse.ts
├── resolve.ts
└── index.ts
```

`parse.ts` contains deterministic input parsing:

- JSON dependency manifests
- bare JSON dependency objects
- YAML dependency sections
- npm package/version specifiers
- scoped package specifiers

`resolve.ts` contains dependency enrichment and input resolution:

- npm registry metadata lookup
- npm package URLs
- repository URL normalization
- GitHub `owner/repo` input
- GitHub repository URLs
- remote HTTP/HTTPS manifest input

Both webviews call these utilities directly. The extension host also reuses `resolvePackage()` when VS Code lazily resolves an editor document link.

## Document links

VS Code-specific document scanning lives in:

```text
src/extension/document-links.ts
```

The extension registers document link providers for:

```text
**/package.json
**/*.yaml
**/*.yml
```

JSON and JSONC dependency sections are discovered through VS Code document symbols.

YAML dependency sections are parsed by indentation.

Package metadata is resolved lazily when VS Code resolves a document link.

## Webviews

Webview source lives under:

```text
src/webviews/
├── inspector/
├── dependency-graph/
└── shared/
```

`src/extension/webviews/openWebviewPanel.ts` is the reusable panel factory. It owns panel creation, CSP, resource URIs, and shared CSS loading.

The Inspector and Dependency Graph are separate React entry points. Each parses and resolves pasted dependency input directly in the browser runtime through `src/utils/`.

The webview CSP permits outbound HTTPS connections so npm metadata and explicitly supplied remote manifests can be resolved without an extension-host message bridge.

Shared types live in `src/shared/`.

## Build targets

The project has separate Vite configurations:

```text
vite.extension.config.ts
vite.webview.config.ts
```

The extension build produces the VS Code runtime bundle.

The webview build is multi-entry and produces browser assets for both views:

```text
dist/webviews/
├── inspector.js
├── dependency-graph.js
├── webview.css
└── chunks/
```

Common React, utility, and shared webview code can be extracted into shared chunks.
