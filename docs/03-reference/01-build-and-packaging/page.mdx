# Build and Packaging

## Build scripts

| Script | Purpose |
| --- | --- |
| `npm run clean` | Removes `dist/` |
| `npm run build:extension` | Builds the VS Code extension host |
| `npm run build:webview` | Builds the React webview |
| `npm run build` | Cleans and builds both targets |
| `npm run watch` | Watches both targets concurrently |
| `npm run typecheck` | Type-checks extension and webview code |
| `npm run lint` | Runs ESLint over `src/` |
| `npm test` | Runs the VS Code test suite |

## Packaging hook

VS Code packaging uses:

```text
vscode:prepublish → npm run build
```

This rebuilds extension output before packaging or publishing.

## Runtime entry point

The extension manifest points VS Code to:

```text
./dist/extension.js
```

## Webview assets

Inspector assets are emitted under:

```text
dist/webview/
```

`src/extension.ts` loads those files through `webview.asWebviewUri(...)` and restricts local resource access to the webview output directory.

## Source boundaries

```text
src/extension.ts       VS Code integration
src/dependencies.ts    parsing and resolution
src/shared/            cross-runtime types and messages
src/webview/           React Inspector
src/test/              extension tests
```

Keep shared contracts browser-safe because they are consumed by both the extension build and the webview build.
