# Build and Packaging

## Build scripts

| Script | Purpose |
| --- | --- |
| `npm run clean` | Removes `out/` |
| `npm run build:extension` | Builds the VS Code extension host |
| `npm run build:webview` | Builds the React webviews |
| `npm run build` | Cleans and builds both targets |
| `npm run watch` | Watches both targets concurrently |
| `npm run typecheck` | Type-checks extension and webview code |
| `npm run lint` | Runs ESLint over `src/` |
| `npm test` | Runs unit and VS Code tests |

## Packaging hook

VS Code packaging uses:

```text
vscode:prepublish → npm run build
```

This rebuilds extension output before packaging or publishing.

## Runtime entry point

The extension manifest points VS Code to:

```text
./out/extension.js
```

## Webview assets

Webview assets are emitted under:

```text
out/webviews/
```

`src/extension/webviews/openWebviewPanel.ts` loads those files through `webview.asWebviewUri(...)` and restricts local resource access to the webview output directory.

## Source boundaries

```text
src/extension.ts                  VS Code entry point
src/extension/document-links.ts  VS Code document-link integration
src/utils/                       browser-safe parsing and resolution
src/shared/                      cross-runtime types
src/webviews/                    React Inspector and Dependency Graph
src/test/                        extension tests
tests/unit/                      unit tests
```

Keep `src/utils/` and `src/shared/` runtime-neutral so they can be consumed by both the extension build and the webview build.
