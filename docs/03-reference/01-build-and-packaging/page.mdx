# Build and Packaging

## Build scripts

| Script | Purpose |
| --- | --- |
| `npm run clean` | Remove `out/` |
| `npm run build:extension` | Build the VS Code extension host |
| `npm run build:webview` | Build the React webviews |
| `npm run build` | Clean and build both production targets |
| `npm run watch` | Watch both production targets |
| `npm run typecheck` | Type-check extension, webview, and preview code |
| `npm run lint` | Run ESLint over `src/` and `previews/src/` |
| `npm run test:unit` | Run Vitest unit tests |
| `npm test` | Run unit and VS Code tests |

## Packaging hook

VS Code packaging uses:

```text
vscode:prepublish → npm run build
```

This rebuilds extension output before packaging or publishing.

## Runtime entry point

The extension manifest points VS Code to:

```text
./out/extension.js
```

## Webview assets

Production webview assets are emitted under:

```text
out/webview-ui/
```

The extension panel loader serves those assets through `webview.asWebviewUri(...)` and restricts local resource access to the webview output directory.

## Production minification

Vite 8 uses Oxc for production webview minification:

```ts
minify: mode === "production" ? "oxc" : false
```

Development builds remain unminified for easier browser and webview debugging.

## Source boundaries

```text
src/extension/     VS Code APIs and extension-host behavior
src/utils/         browser-safe dependency analysis
src/shared/        cross-runtime contracts and types
src/webview-ui/    React Inspector and Dependency Explorer
previews/src/      development-only React Router preview shell
src/test/          extension tests
tests/unit/        unit tests
```

Keep `src/utils/` and `src/shared/` runtime-neutral so both the extension and browser code can consume them.
